# Техническое задание

Приложение для ранжирования фильмов: пространства с фильмами, критериями и участниками.

## 1. Цель и задачи

Разрабатываю приложение для ранжирования фильмов личным списком и по оценкам нескольких участников, чтобы получить прозрачный рейтинг с объяснением результата. Основные пользователи: зрители, которые ведут личный рейтинг, и группы (киноклубы, компании друзей, жюри конкурсов). Ключевые функции: пространства с ролями, оценки по критериям и парные сравнения, три алгоритма ранжирования, объяснение места фильма, экспорт в CSV и PDF.

**Цель:** разработать веб-приложение, в котором пользователь создаёт пространство со своими фильмами, критериями, участниками и алгоритмом расчёта и получает рейтинг с объяснением места каждого фильма.

**Пользователи:** зритель ведёт личный рейтинг просмотренного, а группа (киноклуб, компания друзей, жюри конкурса) собирает общий итог, хотя оценки расходятся и фильм оценивает разное число людей. Каждый входит под своей учётной записью и оценивает от своего имени.

**Режимы пространства.** Режим выбирается при создании и задаёт значения по умолчанию и доступность приглашений, остальная логика одна.

| Режим | Участники | Приглашения | Алгоритм по умолчанию | Критерии |
|-------|-----------|-------------|-----------------------|----------|
| Личный | Один | Отключены | Elo | Не создаются |
| Групповой | Несколько | Включены | Bayesian average | Сюжет, Игра актёров, Режиссура, вес 1 |

Владелец группового пространства может сменить алгоритм по умолчанию и изменить веса критериев. Стартовые критерии редактируются как обычные.

**Задачи:**

1. Спроектировать модель данных: пользователь, пространство, участие в пространстве, фильм, критерий, оценка, сравнение.
2. Реализовать регистрацию, вход и роли внутри пространства.
3. Реализовать создание пространств, вход по коду-приглашению, управление участниками.
4. Реализовать добавление, изменение и удаление фильмов и критериев, ввод оценок, импорт из Excel, тестовые данные.
5. Реализовать три алгоритма ранжирования: Weighted score, Bayesian average, Elo.
6. Реализовать таблицу рейтинга с фильтрацией и сортировкой, объяснение места, сравнение алгоритмов и показатель расхождения оценок.
7. Реализовать экспорт рейтинга в CSV и PDF.
8. Написать тесты на расчёты.

## 5. Алгоритмы ранжирования

Оценки по шкале 1-10. Рейтинг округляется до двух знаков, места расставляются по округлённому значению (тому, что видно в таблице). Фильмы с равным рейтингом получают одно место, следующий фильм - следующий номер без пропуска (1, 1, 2), порядок между равными - по названию.

**Область расчёта:** «Все участники» или «Только я». Данные (оценки или сравнения) фильтруются перед расчётом, сами алгоритмы от области не зависят. При «Только я» используются оценки и сравнения текущего пользователя.

**Weighted score:** сначала для каждого критерия считается среднее по оценившим, затем `Рейтинг = Σ(среднее_i × вес_i) / Σ вес_i` по критериям, у которых есть оценки.

**Bayesian average:** `Рейтинг = (v / (v + m)) × R + (m / (v + m)) × C`, где v - число пользователей, оценивших фильм, R - Weighted score фильма, C - среднее Weighted score по всем фильмам с оценками, m - порог доверия (по умолчанию 3).

**Elo:** начальный рейтинг 1000, ожидаемый результат `E_A = 1 / (1 + 10^((R_B - R_A) / 400))`, новый рейтинг `R_A' = R_A + K × (S_A - E_A)`, K = 32, S = 1 у победителя и 0 у проигравшего. В групповом пространстве учитываются сравнения всех участников в порядке создания. Фильм без сравнений остаётся с начальным рейтингом.

**Особые случаи:**
- Для Weighted score и Bayesian фильм без оценок показывается в конце таблицы без рейтинга.
- Если в пространстве нет критериев (личный режим), Weighted score и Bayesian дают пустой рейтинг, это не ошибка.
- Фильтр по жанру и году применяется после расчёта, поэтому C и рейтинги Elo от фильтра не зависят.
- Параметры: m не меньше 0, K больше 0, начальный рейтинг больше 0. Иначе расчёт отклоняется с ошибкой.

**Объяснение места.**
- Weighted score и Bayesian: среднее по каждому критерию, число оценивших v, R, C, m, итоговый рейтинг и на сколько поправка изменила R.
- Elo: число сравнений, победы и поражения, итоговый рейтинг.

**Сравнение алгоритмов:** для выбранного фильма места по Weighted score, Bayesian и Elo в одной таблице. Фильм без рейтинга по алгоритму показывается без места.

**Разброс (спорные фильмы):** для каждого оценившего считается его собственный Weighted score по фильму, разброс - стандартное отклонение этих значений (по всей совокупности). Если фильм оценили меньше двух пользователей, значение пустое. Колонка есть в таблице Weighted score и Bayesian.

**Подбор пары:** случайная пара фильмов, которую этот пользователь ещё не сравнивал. Если сравнены все пары, берётся любая. Для подбора нужно минимум два фильма.

## 6. Сценарии использования

### С-1. Регистрация и вход

**Основной сценарий:**
1. Пользователь вводит email, имя и пароль, нажимает «Зарегистрироваться».
2. Система создаёт учётную запись и выполняет вход.
3. При следующем визите пользователь входит по email и паролю.

**Альтернативные сценарии:**
- 2а. Email уже занят или пароль короче 8 символов: учётная запись не создаётся, у поля показана ошибка.
- 3а. Неверный email или пароль: система сообщает об ошибке входа.
- 3б. Превышен лимит попыток входа: система просит повторить позже.

### С-2. Создание пространства и вход по коду

**Основной сценарий:**
1. Пользователь нажимает «Создать пространство», вводит название и выбирает режим.
2. Система создаёт пространство, назначает пользователя владельцем и заполняет настройки по режиму.
3. Владелец группового пространства передаёт код-приглашение другим.
4. Другой пользователь вводит код в разделе «Мои пространства».
5. Система добавляет его с ролью «участник» и открывает пространство.

**Альтернативные сценарии:**
- 5а. Код не найден или пространство личное: система сообщает, что войти нельзя.
- 5б. Пользователь уже в пространстве: система просто открывает его.
- 5в. Превышен лимит попыток ввода кода: система просит повторить позже.

### С-3. Добавление фильма и импорт

**Предусловие:** роль владельца или участника.

**Основной сценарий:**
1. Пользователь открывает вкладку «Фильмы» и нажимает «Добавить фильм».
2. Заполняет название, год, жанр, режиссёра и сохраняет.
3. Система сохраняет фильм и показывает его в списке.
4. Для массовой загрузки пользователь нажимает «Импорт из Excel» и выбирает файл .xlsx.
5. Система проверяет файл, сохраняет корректные строки и показывает отчёт: сколько строк добавлено, какие отклонены и почему.

**Альтернативные сценарии:**
- 3а. Обязательное поле пустое или год вне диапазона 1888 - текущий год + 5: фильм не сохраняется, у поля показана ошибка.
- 3б. Фильм с таким названием и годом уже есть: система сообщает о дубликате.
- 5а. Файл другого формата, без обязательных столбцов или с заголовком, который не совпадает с названием критерия: файл отклоняется целиком.
- 5б. Фильм уже есть: он не дублируется, к нему добавляются оценки загрузившего, прежняя оценка по критерию заменяется.
- 5в. В строке неверное поле, например балл вне диапазона 1-10: строка отклоняется, остальные сохраняются.

### С-4. Выставление оценок

**Предусловие:** роль владельца или участника, в пространстве есть фильм и критерий.

**Основной сценарий:**
1. Пользователь открывает фильм.
2. Вводит баллы по критериям.
3. Нажимает «Сохранить оценки».
4. Система сохраняет оценки от имени пользователя и показывает обновлённый рейтинг фильма.

**Альтернативные сценарии:**
- 2а. Критериев нет: владельцу система предлагает создать критерий, остальным сообщает, что оценивать пока нечего.
- 2б. У пользователя уже есть оценка по критерию: новое значение заменяет старое.
- 3а. Балл вне диапазона 1-10 или не число: оценки не сохраняются, у поля показана ошибка.

### С-5. Парное сравнение

**Предусловие:** роль владельца или участника.

**Основной сценарий:**
1. Пользователь открывает вкладку «Сравнение».
2. Система показывает пару фильмов по правилу подбора.
3. Пользователь выбирает лучший.
4. Система сохраняет сравнение, обновляет рейтинги Elo и показывает следующую пару.
5. Если выбор ошибочный, пользователь нажимает «Отменить последнее сравнение». Система удаляет последнее сравнение этого пользователя в пространстве, рейтинг Elo пересчитывается при следующем запросе.

**Альтернативные сценарии:**
- 2а. Фильмов меньше двух: система сообщает, что нужно минимум два.
- 5а. У пользователя нет сравнений в этом пространстве: система сообщает, что отменять нечего.

### С-6. Просмотр рейтинга с объяснением

**Основной сценарий:**
1. Пользователь открывает вкладку «Рейтинг», система показывает таблицу по алгоритму пространства по умолчанию.
2. Пользователь выбирает другой алгоритм и область («Все участники» или «Только я»), система пересчитывает таблицу.
3. Пользователь фильтрует по жанру и году, сортирует.
4. Пользователь выбирает фильм, система показывает объяснение места и места фильма по трём алгоритмам.

**Альтернативные сценарии:**
- 1а. Для Weighted score и Bayesian у фильма нет оценок: он показывается в конце таблицы без рейтинга.
- 1б. В личном пространстве нет критериев: для Weighted score и Bayesian таблица пустая.
- 1в. Для Elo нет сравнений: у всех фильмов начальный рейтинг, система предлагает перейти к сравнению.

**Постусловие:** при просмотре данные не меняются.

### С-7. Экспорт рейтинга

**Основной сценарий:**
1. Пользователь выбирает алгоритм, область и фильтры.
2. Нажимает «Экспорт CSV» или «Экспорт PDF».
3. Система формирует файл из текущей таблицы, браузер скачивает его.

**Альтернативные сценарии:**
- 3а. Таблица пуста: система сообщает, что экспортировать нечего.

**Постусловие:** содержимое файла совпадает с таблицей на экране.

### С-8. Управление участниками

**Предусловие:** роль владельца.

**Основной сценарий:**
1. Владелец открывает вкладку «Участники».
2. Меняет роль участника на «наблюдатель» или обратно.
3. Для удаления участника нажимает «Убрать» и подтверждает.
4. Система удаляет участника, его оценки и сравнения в этом пространстве.

**Альтернативные сценарии:**
- 2а. Владелец пытается изменить роль или убрать самого себя: система не позволяет.

## 7. Ограничения

**Стек:** NestJS (TypeScript), TypeORM, PostgreSQL, React + Vite (TypeScript), Jest, развёртывание на Render.

**Авторизация:** регистрация и вход по email и паролю. Без входа через внешние сервисы, подтверждения почты, восстановления пароля и удаления учётной записи.

**Формат экспорта:**
- CSV: UTF-8 с BOM, разделитель `;`, первая строка - заголовки. Столбцы: место, название, год, жанр, режиссёр, рейтинг, алгоритм. Для Weighted score и Bayesian добавляется столбец «Разброс».
- PDF: таблица рейтинга с названием пространства, алгоритмом и датой формирования.

**Формат импорта:** .xlsx, один лист, первая строка - заголовки. Одна строка - один фильм. Столбцы: «Название», «Год», «Жанр», «Режиссёр» и по желанию по одному столбцу на каждый критерий пространства. Заголовок критерия совпадает с его названием, пустая ячейка - оценки нет. Оценки ставятся от имени пользователя, загрузившего файл.

**Не реализуется:** слепое голосование жюри, комментарии, уведомления, рекомендации, интеграция с внешними API.
