# Техническое задание

Приложение для ранжирования кинопродукции.

## 1. Цель и задачи

**Цель:** разработать веб-приложение для ведения каталога фильмов и расчёта их рейтинга по нескольким методикам.

**Задачи:**

1. Спроектировать модель данных: фильм, критерий оценки, оценщик, оценка, сравнение.
2. Реализовать добавление, изменение и удаление фильмов, критериев и оценщиков.
3. Реализовать ввод данных: формы, импорт из Excel, тестовые данные.
4. Реализовать три алгоритма ранжирования: Weighted score, Bayesian average, Elo.
5. Реализовать таблицу рейтинга с фильтрацией и сортировкой.
6. Реализовать экспорт рейтинга в CSV и PDF.
7. Написать тесты на расчёты.

## 4. Алгоритмы ранжирования

Оценки по шкале 1-10.

**Weighted score:** сначала для каждого критерия считается среднее по оценщикам, затем `Рейтинг = Σ(среднее_i × вес_i) / Σ вес_i` по критериям, у которых есть оценки.

**Bayesian average:** `Рейтинг = (v / (v + m)) × R + (m / (v + m)) × C`, где v - число оценщиков, оценивших фильм, R - Weighted score фильма, C - среднее Weighted score по всем фильмам с оценками, m - порог доверия (по умолчанию 3).

**Elo:** начальный рейтинг 1000, ожидаемый результат `E_A = 1 / (1 + 10^((R_B - R_A) / 400))`, новый рейтинг `R_A' = R_A + K × (S_A - E_A)`, K = 32, S = 1 у победителя и 0 у проигравшего. Сравнения учитываются в порядке создания.

## 5. Сценарии использования

Действующее лицо - пользователь.

### UC-1. Добавление фильма

**Предусловие:** открыт раздел «Фильмы».

**Основной сценарий:**
1. Пользователь нажимает «Добавить фильм».
2. Заполняет название, год, жанр, режиссёра.
3. Нажимает «Сохранить».
4. Система сохраняет фильм и показывает его в списке.

**Альтернативные сценарии:**
- 4а. Обязательное поле пустое или год вне диапазона 1888 - текущий год + 5: фильм не сохраняется, у поля показана ошибка.
- 4б. Фильм с таким названием и годом уже есть: система сообщает о дубликате.

**Постусловие:** фильм добавлен в БД.

### UC-2. Импорт из Excel

**Предусловие:** открыт раздел «Фильмы».

**Основной сценарий:**
1. Пользователь нажимает «Импорт из Excel» и выбирает файл .xlsx.
2. Система проверяет файл и читает строки.
3. Система сохраняет корректные строки. Оценщик, которого ещё нет, создаётся.
4. Система показывает отчёт: сколько строк добавлено, какие отклонены и почему.

**Альтернативные сценарии:**
- 2а. Файл другого формата или без нужных столбцов: файл отклоняется целиком.
- 3а. В строке пустой «Оценщик» или другое поле неверно: строка отклоняется, остальные сохраняются.

**Постусловие:** фильмы, оценки и новые оценщики из корректных строк добавлены в БД.

### UC-3. Выставление оценки

**Предусловие:** есть хотя бы один фильм и один критерий.

**Основной сценарий:**
1. Пользователь открывает карточку фильма.
2. Выбирает оценщика.
3. Вводит баллы по критериям.
4. Нажимает «Сохранить оценки».
5. Система сохраняет оценки и показывает обновлённый рейтинг фильма.

**Альтернативные сценарии:**
- 2а. Оценщиков нет: система предлагает создать оценщика.
- 3а. Критериев нет: система предлагает создать критерий.
- 3б. По критерию у этого оценщика уже есть оценка: новое значение заменяет старое.
- 5а. Балл вне диапазона 1-10 или не число: оценки не сохраняются, у поля показана ошибка.

**Постусловие:** по каждой тройке «фильм + критерий + оценщик» в БД одна оценка.

### UC-4. Расчёт рейтинга тремя алгоритмами

**Предусловие:** есть фильмы с оценками.

**Основной сценарий:**
1. Пользователь открывает раздел «Рейтинг».
2. Система показывает таблицу по Weighted score.
3. Пользователь выбирает другой алгоритм.
4. Система пересчитывает и показывает таблицу.
5. Пользователь фильтрует по жанру и году, сортирует.

**Сравнение для Elo:**
1. Пользователь открывает «Сравнение».
2. Система показывает два фильма.
3. Пользователь выбирает лучший.
4. Система сохраняет сравнение и обновляет рейтинги обоих фильмов.

**Альтернативные сценарии:**
- 2а. Фильмы без оценок система показывает в конце таблицы без рейтинга.
- Сравнение 2а. Фильмов меньше двух: система сообщает, что нужно минимум два.
- 4а. Для Elo нет сравнений: у всех фильмов начальный рейтинг, система предлагает перейти к сравнению.

**Постусловие:** при просмотре данные не меняются, при сравнении обновляются рейтинги Elo.

### UC-5. Экспорт рейтинга

**Предусловие:** открыта таблица рейтинга.

**Основной сценарий:**
1. Пользователь выбирает алгоритм и фильтры.
2. Нажимает «Экспорт CSV» или «Экспорт PDF».
3. Система формирует файл из текущей таблицы.
4. Браузер скачивает файл.

**Альтернативные сценарии:**
- 3а. Таблица пуста: система сообщает, что экспортировать нечего.

**Постусловие:** содержимое файла совпадает с таблицей на экране.

## 6. Ограничения

**Стек:** NestJS (TypeScript), TypeORM, PostgreSQL, React + Vite (TypeScript), Jest, развёртывание на Render.

**Формат экспорта:**
- CSV: UTF-8 с BOM, разделитель `;`, первая строка - заголовки. Столбцы: место, название, год, жанр, режиссёр, рейтинг, алгоритм.
- PDF: таблица рейтинга с названием алгоритма и датой формирования.

**Формат импорта:** .xlsx, один лист, первая строка - заголовки, обязательный столбец «Оценщик».

**Авторизация:** в базовой версии нет, приложение однопользовательское.

**Не реализуется:** интеграция с внешними API (TMDb, Кинопоиск).
